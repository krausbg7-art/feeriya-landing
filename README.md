# Феерия.ру — «Фейерверки по поводу»

Статическая посадочная страница для feeriya.ru: пользователь выбирает повод
(Новый год, свадьба, день рождения, юбилей), видит подборку из каталога и
переходит на основной сайт за покупкой. Без сборщика — открывается любым
статическим сервером.

## Структура файлов

```
index.html                    — разметка страницы
assets/styles.css             — стили
assets/app.js                 — логика: рендер, фильтр по бюджету, метрика
data/catalog.json             — поводы, разделы каталога, бюджеты, доверие
data/products.json            — товары по 15 слотов на повод (см. ниже)
scripts/build-catalog.mjs     — конвертер YML-фида в data/products.json
.github/workflows/deploy.yml  — деплой на GitHub Pages при пуше в main
package.json                  — npm-скрипты (start, build:catalog)
```

## Запуск локально

Зависимостей нет, нужен только статический сервер:

```
npm start
# или
python3 -m http.server 5173
```

Открыть http://localhost:5173

## Заполнение data/products.json вручную

Файл делится на 4 массива по поводам (`new-year`, `wedding`, `birthday`,
`anniversary`), в каждом — ровно 15 слотов. Слот без товара выглядит как
пунктирная карточка-заглушка на странице с подсказкой, куда его дозаполнить.

Поля товара:

| Поле       | Тип    | Описание                                   |
|------------|--------|---------------------------------------------|
| `id`       | string | артикул/ID товара в магазине               |
| `name`     | string | название                                    |
| `price`    | number | цена в рублях                               |
| `shots`    | number | количество залпов                          |
| `caliber`  | string | калибр, например `1.2"` или `35 мм`        |
| `height`   | number | высота подъёма в метрах                    |
| `duration` | number | время работы в секундах                    |
| `path`     | string | путь товара на feeriya.ru (без домена)     |

Пример заполненного слота:

```json
{
  "id": "46055",
  "name": "Архитектор",
  "price": 24990,
  "shots": 100,
  "caliber": "1.2\"",
  "height": 60,
  "duration": 90,
  "path": "/batarei_super_saljutov/arhitektor"
}
```

Пустой слот-заготовка:

```json
{ "id": "", "name": "", "price": 0, "shots": 0, "caliber": "", "height": 0, "duration": 0, "path": "" }
```

Слоты заполняются сверху вниз — так на странице заполненные карточки идут
подряд, а заготовки — в конце списка.

## Автоматическая сборка из YML-фида

Вместо ручного заполнения можно скормить скрипту YML-фид магазина
(Яндекс.Маркет формат), и он сам разложит товары по поводам:

```
npm run build:catalog -- <url-или-путь-к-фиду>
npm run build:catalog -- https://www.feeriya.ru/yandex.yml
npm run build:catalog -- ./feed.xml --limit 500
```

Скрипт (`scripts/build-catalog.mjs`) без внешних зависимостей: парсит офферы,
достаёт залпы/калибр/высоту/время работы из `<param>` или угадывает их по
названию/описанию, раскладывает по поводам по ключевым словам и диапазону
цены, берёт до 15 товаров на повод равномерно по цене и перезаписывает
`data/products.json`.

## Яндекс.Метрика

Счётчик `20920177` подключается автоматически (`assets/app.js`). Страница
шлёт три цели — их нужно завести в интерфейсе Метрики (Настройка → Цели):

| Цель              | Когда срабатывает                          |
|-------------------|---------------------------------------------|
| `occasion_select` | переключение повода                        |
| `budget_filter`   | выбор фильтра по бюджету                   |
| `landing_click`   | клик по любой ссылке с `data-track`        |

## Город

Город определяется по приоритету: параметр `?city=spb` в адресе →
значение в `localStorage` (`feeriya_city`) → Москва по умолчанию. Поддержаны
ключи: `msk`, `spb`, `ekb`, `nsk`, `kzn`, `nn`.

## Дедлайн доставки

Плашка над блоком повода берёт даты из `data/catalog.json` →
`meta.deliveryDeadlines` (`msk` и `regions`) и показывается только когда до
даты осталось меньше 75 дней — то есть основную часть года она скрыта.

## Публикация на GitHub Pages

Репозиторий уже является текущим `origin` — достаточно закоммитить и
запушить в `main`, workflow задеплоит автоматически. Дальше в репозитории
нужно один раз включить: **Settings → Pages → Build and deployment → Source:
GitHub Actions**. Адрес страницы появится там же после первого успешного
деплоя.

## Свой домен

Чтобы страница открывалась по своему адресу вместо `github.io`:

1. Добавить файл `CNAME` в корень репозитория с одной строкой — доменом
   (например `na-novyy-god.feeriya.ru`).
2. У регистратора/DNS-провайдера добавить CNAME-запись, указывающую этот
   поддомен на `krausbg7-art.github.io`.
3. В Settings → Pages указать тот же домен в поле Custom domain.

## Ограничения

GitHub Pages отдаёт только статику — никакого серверного кода, форм с
обработкой на сервере или скрытых ключей здесь быть не может. Это годится
для быстрого прототипа/лендинга, но в перспективе такие страницы лучше
перенести прямо на feeriya.ru как обычные разделы каталога
(`/na-novyy-god`, `/na-svadbu` и т.д.), чтобы они жили на основном домене и
работали с той же корзиной и SEO-историей сайта.
